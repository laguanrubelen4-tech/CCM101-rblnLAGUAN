# Laboratory 01 – Welcome to the Cloud

## Mission Overview

This laboratory activity introduces the fundamentals of cloud-based Linux environments and basic Linux system administration. The activity was completed using the KillerCoda Linux Playground and GitHub. The main goal is to become familiar with using a cloud-based terminal, managing users and directories, checking system information, creating Markdown files, and documenting laboratory activities in a GitHub repository.

## Objectives

- Access and use a cloud-based Linux environment through KillerCoda.
- Create and manage a Linux user account.
- Navigate the Linux file system using terminal commands.
- Gather basic information about the Linux system.
- Create and organize directories and Markdown files.
- Create and manage a GitHub repository.
- Document laboratory activities using Markdown.
- Capture screenshots as evidence of completed tasks.

## Activities Performed

### Checkpoint 1 – Enter the Cloud

- Launched an Ubuntu Linux Playground using KillerCoda.
- Verified that the terminal was functioning correctly.
- Created a new Linux user with a home directory, Bash shell, and sudo privileges.
- Logged in to the newly created user account.
- Recorded the current username, working directory, and hostname.

### Checkpoint 2 – Meet Your Environment

The Linux environment was investigated to determine:

- Linux distribution
- Kernel version
- CPU information
- Total memory
- Available disk space

The collected information was recorded in `system-information.md`.

### Checkpoint 3 – Build Your Workspace

Created the required directory structure inside the home directory.

The `Notes` directory contains the following Markdown file:

- `about-me.md`

### Checkpoint 4 – Create Your Cloud Computing Portfolio

Created a public GitHub repository named:

`CCM101-cbadongen`

The repository contains the laboratory files, documentation, and screenshots required for the activity.

### Checkpoint 5 – Document Your Mission

Created this `README.md` file to document the mission overview, objectives, activities, Linux commands used, and skills learned.

### Checkpoint 6 – Capture Evidence

Screenshots were captured to provide evidence of the completed activities, including:

- KillerCoda Playground
- Terminal session
- Created directory structure
- GitHub repository homepage
- Repository file structure

### Checkpoint 7 – Complete the Mission

Reviewed the repository to ensure that all required files, folders, and screenshots were present. The final changes were committed and pushed to GitHub.

## Linux Commands Used

| Command | Purpose |
|---|---|
| `whoami` | Displays the current username |
| `pwd` | Displays the current working directory |
| `hostname` | Displays the hostname |
| `ls` | Lists files and directories |
| `cd` | Changes the current directory |
| `mkdir` | Creates directories |
| `touch` | Creates a new file |
| `cat` | Displays file contents |
| `nano` | Opens a text file for editing |
| `clear` | Clears the terminal screen |
| `sudo` | Executes commands with administrative privileges |
| `adduser` | Creates a new Linux user |
| `su` | Switches to another user |
| `uname` | Displays system and kernel information |
| `lscpu` | Displays CPU information |
| `free` | Displays memory information |
| `df` | Displays disk space information |
| `git init` | Initializes a Git repository |
| `git add` | Adds files to the Git staging area |
| `git commit` | Saves changes to the Git repository |
| `git push` | Uploads changes to GitHub |
